# CQA: оценка качества чатов и звонков

**Команда «Я и Нурай»** · Freedom Broker / CQA Hackathon

Система берёт диалог оператора с клиентом, оценивает его LLM-моделью по чек-листу из 8 критериев и показывает итог из 100. Для каждого пункта она даёт обоснование и указывает место в диалоге. Оператор может оспорить оценку, а проверяющий ответить на апелляцию и запустить пересмотр.

> **Для проверяющего:** результаты лежат в [`results/dev/results.json`](results/dev/results.json) (60 чатов + 5 звонков) и [`results/prod/results.json`](results/prod/results.json) (10 контрольных чатов), формат JSON 1.0 из гайда.

---

## Быстрый старт (Windows)

```bash
scripts\start_all.bat
```

Один двойной клик:
1. создаёт `.env` из `.env.example`, если его нет;
2. запускает Ollama и загружает модель (при `LLM_PROVIDER=ollama`);
3. запускает API на `http://127.0.0.1:8000`, документация на `/docs`;
4. запускает фронтенд на `http://127.0.0.1:5500` и открывает его в браузере.

Затем нажмите «Загрузить JSON» и выберите `src/hackathon_26_freedombank/data.json`.

**Требования:** Python ≥ 3.14, [uv](https://docs.astral.sh/uv/), [Ollama](https://ollama.com) с моделью из `OLLAMA_MODEL` (или ключ Gemini).

```bash
uv sync
```

## Получить results.json без UI

```bash
uv run python scripts/export_results.py --input src/hackathon_26_freedombank/data.json --out results/dev/results.json
```

```bash
uv run python scripts/export_results.py --input prod.json --out results/prod/results.json
```

- Скрипт всегда оценивает **стандартными 8 критериями** и проверяет файл по правилам гайда: все 8 критериев, уникальные ID, допустимые значения, `critical_flag` совпадает с `critical`.
- Прогресс сохраняется после каждого диалога, `--resume` продолжает с места остановки, `--limit 3` нужен для быстрой проверки.
- Сбой модели не прячется: такой диалог попадает в файл со `status: "error"` и причиной, как требует гайд.

## Как считается оценка

| criterion_id | Критерий | Значение | Вес |
|---|---|---|---|
| `contact` | Установление контакта | true / false | 10 |
| `discovery` | Выявление потребности | true / false / null | 15 |
| `identification` | Идентификация | true / false / null | 20 |
| `consultation` | Корректная и полная консультация | 0, 5, 10, 15, 20 / null | 20 |
| `empathy` | Эмпатия и клиентоориентированность | true / false | 15 |
| `dialogue` | Ведение, скорость, грамотность | 0, 4, 7, 10 | 15 |
| `closure` | Завершение | true / false / null | 5 |
| `critical` | Грубые ошибки | true / false | — |
| `pushback` | *Отталкивание (доп., выключен по умолчанию)* | true / false / null | 10 |

- `null` = N/A: критерий исключается, а его вес пропорционально делится между остальными. Итог считается из 100 и округляется до 2 знаков.
- `critical` **не обнуляет** итог, `critical_flag` передаётся отдельно (по гайду).
- `pushback` — дополнительный критерий для UI: оператор долго (дольше 3 минут) брал диалог после ИИ-ассистента и/или проявлял скрытую агрессию. Это нарушение, поэтому «Да» = 0 баллов.
- Порог первой реакции 3 минуты. Теги и вложения не оцениваются. Реплики бота и системные события используются только как контекст.

**Надёжность ответа LLM.** Модели передаётся JSON Schema: у каждого критерия только допустимые значения, N/A только там, где он разрешён. Модель сначала пишет обоснование, потом ставит оценку. Ответ дополнительно валидируется, при ошибке модель получает один повторный запрос со списком проблем. Для Ollama отключено «размышление» (thinking), контекст увеличен до 16K, ответ ограничен по длине, temperature = 0.

## Интерфейс

| Окно | Что там |
|---|---|
| **1** | Список критериев с «+» (включить в оценку) и комментарием для ИИ к каждому, аудиоплеер для звонков, расшифровка с номерами реплик `#N` и таймкодами |
| **2** | «Показать итоговую оценку»: модальное окно с числом из 100 и пометкой о грубой ошибке |
| **3** | Итог из 100 и пункты **3.1…3.N**: вердикт и короткое обоснование, грубые ошибки выделены красным, справа синяя ссылка «Оспорить» |
| **6** | Момент в диалоге для выбранного пункта: «ошибка здесь», «должно было прозвучать после…» или «хороший пример», с цитатой, таймкодом и кнопкой ▶ для прослушивания фрагмента |
| **4 / 5** | Апелляция: квадратик с номером пункта и поле объяснения, кнопки «Сохранить обращение» и «Сохранить и отправить» |

- **Режим проверяющего** включается вкладкой справа. Оспоренные пункты выделяются красным, под ними видны комментарии оператора, в окне 4 проверяющий пишет ответы. В окне 2 две разнесённые кнопки:
  - **«Подтвердить оценку»**: апелляция отклонена, итог прежний;
  - **«Пересмотреть оценку»**: ИИ заново оценивает **только** пункты, на которые проверяющий ответил, с учётом комментариев. Итог пересчитывается, а старая оценка сохраняется в истории.
- **«Настройки»**: какие критерии видны в окне 1 (галочки) и вес каждого (ползунок 0–50, доля от 100 % пересчитывается на лету).
- **«Редактор критериев»**: тексты, шкалы, новые критерии. Каждое сохранение создаёт новую версию чек-листа, и прошлые оценки остаются привязаны к своей версии.
- **Языки:** интерфейс на RU / KZ / EN. ИИ пишет обоснования на языке диалога.
- **Пакетная оценка:** «Оценить все записи» с повтором при лимитах LLM, фильтр «Все / Оценённые / Не оценённые / С ошибкой / С апелляцией», выгрузка CSV и results.json.

## Архитектура

```
браузер (front/, ES-модули, без сборки)
   │  fetch JSON
   ▼
FastAPI (src/…/main.py) ── routers ── evaluation/ ── llm/ ──► Ollama (локально) | Gemini (API)
   │
   ▼
SQLite app.db (SQLModel): conversation · checklist (версии) · evaluation · appeal
```

| Метод | Путь | Назначение |
|---|---|---|
| `GET / POST` | `/conversations` | список с итогами и статусами / загрузка `data.json` |
| `GET` | `/conversations/{id}` | диалог с транскриптом |
| `POST` | `/conversations/{id}/evaluate` | оценить активным чек-листом |
| `GET` | `/conversations/{id}/evaluation` | последняя оценка |
| `GET` | `/evaluations/results.json` · `/evaluations/export.csv` | выгрузки |
| `GET / PUT` · `POST` | `/checklist` · `/checklist/reset` | чек-лист (каталог критериев) |
| `GET / PUT` | `/conversations/{id}/appeal` | апелляция: чтение / черновик |
| `POST` | `/appeals/{id}/submit · /confirm · /revise` | отправить / подтвердить / пересмотреть |
| `PUT` | `/appeals/{id}/review` | ответы проверяющего |

## Настройки (`.env`)

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `LLM_PROVIDER` | `ollama` | `ollama` (локально) или `gemini` (API) |
| `OLLAMA_MODEL` | `qwen3.5-9b-gpu` | модель Ollama |
| `OLLAMA_THINK` | `false` | thinking-модели без этого «думают» бесконечно |
| `OLLAMA_NUM_CTX` | `16384` | самый длинный диалог занимает ~7.6K токенов |
| `OLLAMA_NUM_PREDICT` · `OLLAMA_TIMEOUT` | `4096` · `600` | лимит ответа и время ожидания |
| `GEMINI_API_KEY` · `GEMINI_MODEL` | — | для облачного варианта |
| `TEAM_NAME` | `Я и Нурай` | `team_name` в results.json |
| `CORS_ORIGINS` | `:5500` | откуда фронтенду можно ходить в API |

**Модель в results.json:** `mode` определяется автоматически: `local` для Ollama, `external_api` для Gemini, `hybrid` если использовались обе.
